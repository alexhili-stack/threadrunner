# Browser design and interaction review

Reviewed the actual GitHub Pages game and the local refined build in Chromium. The goal was to help friends start playing, understand the three thread tools and use smaller screens while preserving Threadrunner's existing identity. Impeccable guided the refinement, Product Design supplied the flow audit, Game Studio supplied the HUD/playtest approach, and Sites supplied static preview and packaging guidance. Hosting remains GitHub Pages as requested.

1. **Arrival — healthy.** One primary Play action, genuine loading progress, retryable startup errors and links to controls/licenses. The existing courier artwork, condensed type and teal signal establish the game immediately. The first WebAssembly download is approximately 42 MB.
2. **Menu — healthy, with accessibility limits.** Campaign and Thread lessons remain visible and keyboard focus works. Native Godot menus are rendered inside a canvas; their individual buttons are not exposed as HTML controls. A full screen-reader audit is not claimed.
3. **Thread lesson — improved.** Reachable square terminals now gain a paper outline matching the real interaction test. Binding-aware hints name the available action. Lesson copy advances from bridge/swing/relay tasks to reaching the exit. Rewind reports exhaustion and requires release; holding an empty trail no longer suspends gravity. The regression was reproduced against the actual CharacterBody2D before the fix.
4. **Phone controls — improved.** The 390px layout separates movement and jump under opposite thumbs, places four tool/pause controls in a second row, and displays the current lesson objective outside the small canvas. Touch visibility adapts when the window changes size. Tool controls report actual availability and stored thread. A focus transfer during touch input was removed; actual touch-button movement and pause were then observed in the browser.

The baseline and refined captures are retained in local `artifacts/design-audit`. Browser layout checks include 390×844, 844×390 and the normal desktop viewport. Small portrait playfields still benefit from rotating the phone or using fullscreen. Physical phones, Safari, physical gamepads, subjective sound quality and full assistive-technology compatibility were not tested.
